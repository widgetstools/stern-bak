# Packaging workstream — what changed and why

Record of the work that made `@wellsfargo-starui/*` publishable to teams
**without repo access**. Written to be picked up cold in a later session.

- **Merged to `main`** as of 2026-07-31, fast-forward, head `b20bc86a`.
- **Standard applied:** ag-grid's — install the package, import one
  stylesheet, done. No consumer edits to `vite.config`, `tailwind.config`,
  `postcss.config`, or `tsconfig`.
- **Reference:** [`EXTERNAL_CONSUMPTION.md`](./EXTERNAL_CONSUMPTION.md) is the
  consumer-facing contract. This file is the history behind it.

## 1. Module cycles and undeclared dependencies (`af80b131`)

External installs hard-fail on things an in-repo build hides through hoisted
symlinks and source aliases.

- **`engine` imported itself by package name** from 10 customizer modules
  while its root barrel re-exported those same modules — a true runtime
  cycle. From a packed tarball the self-reference resolves to a *second copy*
  of the barrel (`dist`) alongside the `src` graph. All ten now import
  concrete modules relatively.
- `host-data-react` — `HubInspectorDrawer` closed a 4-file barrel cycle;
  now uses `useDataServicesContext` directly.
- `host-data` — `config/store` ↔ `providers/appdata/store` traded constants;
  moved to a leaf `config/componentTypes.ts`.
- `openfin-platform` — `platformBootstrap` ↔ `registryHostEnv` cycled on
  `DEFAULT_APP_ID`; moved to a leaf `defaultAppId.ts`.
- `design-system` — an inferred return type made `tsc` emit `import("..")`
  into the `.d.ts`, a dist-only declaration cycle; annotated explicitly.
- **Undeclared deps added:** `grid` += `icons-svg`, `shared-types`;
  `host-data-react` += `host-config`.

## 2. Real dist builds (`0887f768`)

`grid`, `config-browser`, `host-data-react`, `workspace-setup-react` and
`icons-svg` shipped **raw `.ts`/`.tsx`** — `exports` pointed at `src/` and
`build` was an `echo` no-op. Unusable outside Vite. All five now emit `dist`
with `types`+`import` conditions, `files: ["dist"]`, and CSS copied in.

`scripts/packageDistFinalize.mjs` rewrites extensionless relative specifiers
(`./x` → `./x.js`) in emitted JS and `.d.ts` — Node, webpack, Next and `tsc`
all require fully-specified paths. **171** such specifiers existed across
five packages; now zero. Also converted 41 self-referencing imports to
relative paths.

`scripts/pack-npm.mjs` (`npm run pack:npm`) packs each package
**individually under its real name**, drops `private: true`, and rewrites
workspace `"*"` ranges to concrete `^version`. Distinct from
`npm run propagate`, which packs per-bucket tarballs for the in-repo demos
and was never installable externally.

## 3. CSS — zero-config, then opt-in reset (`0887f768`, `b20bc86a`)

Originally the utility CSS was generated by **each app's** Tailwind scanning
our package sources; an external team would have had to replicate the whole
toolchain plus `node_modules` content globs. `design-system` now compiles it
at package-build time.

The first cut shipped `full.css` **with Tailwind preflight embedded** — so
importing it rewrote the consumer's own `h1` margins, list markers and
border defaults. That is not what libraries do. Split in `b20bc86a`:

| Export | Contents | When |
|---|---|---|
| `./styles.css` | tokens + `@font-face` + component utilities + grid chrome | always — the one required import |
| `./reset.css` | Tailwind preflight alone | opt-in; skip if the app has its own reset |
| `./css` | tokens only | consumers running their own Tailwind against our preset |

`styles.css` keeps only what the utilities are mechanically useless without,
inside `@layer wf-base` so any unlayered consumer rule wins:

- `box-sizing` + `border-width: 0` + `border-style: solid` on `*` —
  Tailwind's `border-*` utilities set **width only**, so without these a
  `border` class renders nothing.
- typography inheritance on `button`/`input`/`select`/`textarea`. Added only
  after a browser check caught our Button rendering in **Arial**: form
  controls do not inherit type from ancestors. This is the one place the
  sheet touches consumer elements, and it is documented as such.

`build-full-css.ts` → `build-styles-css.ts`. It now **fails loudly** on a
missing input; an `existsSync` filter had silently dropped a stylesheet when
`editingToolbar.css` moved.

## 4. Fonts — self-hosted (`b20bc86a`)

`theme.css` carried `@import url('https://fonts.googleapis.com/...')` — a
runtime call to an external host that corporate CSP/egress typically blocks,
degrading silently to system fonts. Inter and JetBrains Mono now ship inside
the package: variable `woff2`, latin + latin-ext, subsetted by reusing
Fontsource's own `unicode-range` values, with OFL-1.1 licences in
`dist/fonts/`.

## 5. SharedWorker — resolves itself (`b20bc86a`)

`workerScriptUrl` is now **optional** on all 7 public signatures. Omitted,
the library uses the inline `new URL(..., import.meta.url)` form every
bundler statically detects. An explicit URL still wins for CDN / OpenFin
manifest / `<script>` hosting.

**The trap worth remembering.** Pointing that URL at the *source* entry
(`../worker/defaultEntry.js`) **failed the consumer's build outright**:

> `Invalid value "iife" for option "worker.format" — UMD and IIFE output
> formats are not supported for code-splitting builds.`

Vite's default `worker.format` is `iife`, and the source graph reaches a lazy
`import('@stomp/stompjs')`, which forces code-splitting. A library **cannot**
set `worker.format` for its consumer, and making that import static would
drag stompjs into every consumer's **main** bundle (`stomp.ts` is reachable
from the package root entry). Fix: point at the pre-built esbuild asset
`../../assets/data-services-worker.mjs` — stompjs inlined, zero dynamic
imports, nothing to split. **Two call sites had this bug**;
`createDataServicesClient` only surfaced after `createDataServicesWorker`
was fixed.

Also added an SSR guard (`typeof SharedWorker === 'undefined'` → named
error) and removed the dead `searchParams` mutation that was defeating
static analysis.

**Known caveat, documented:** Vite *dev* prebundles bare `node_modules`
imports into `.vite/deps/`, relocating the module and breaking the relative
resolution. A package cannot opt itself out of Vite's optimizer, so Vite dev
users add one line: `optimizeDeps: { exclude: ['@wellsfargo-starui/host-data'] }`.
`vite build` and every other bundler need nothing. A Blob-URL worker would
avoid even that but is **not viable for a SharedWorker** — each
`createObjectURL` yields a distinct URL, so every window would get its own
worker instead of sharing one hub.

## 6. Dependency policy — minimal peers (`b20bc86a`)

Peers **only** for genuine singletons the consumer also owns; everything else
is a normal dependency so consumers install nothing extra.

- **Kept as peers:** `react`, `react-dom`, `ag-grid-community`/`-enterprise`/
  `-react` (ModuleRegistry singleton + consumer-held licence),
  `@tanstack/react-query`, `lucide-react`.
- **`@openfin/*` → optional peers** on `openfin-platform`. A browser-only
  consumer now installs **zero** OpenFin packages (verified:
  `node_modules/@openfin` absent) instead of two large runtimes it never
  loads. Safe because `config-browser` / `host-wrapper-react` reach OpenFin
  only via the `@wellsfargo-starui/openfin-platform/config` subpath, whose
  graph holds `import type` references alone — and OpenFin apps already
  declare the three packages themselves.
- **`@stomp/stompjs` → dependency** (was an optional peer). Once the consumer
  owns the worker graph it must resolve.
- **`tailwindcss` → optional peer** on `ui` + `design-system` (was an exact
  `3.4.1` hard peer, which caused ERESOLVE in external installs).
- **Stale removed:** `zustand`, `clsx`, `class-variance-authority`,
  `tailwind-merge`, `@radix-ui/react-alert-dialog` from `grid`; the same from
  `config-browser` and `workspace-setup-react`; `@stomp/stompjs` + `@openfin/*`
  from `widgets-react`; `ag-grid-enterprise`/`-react` peers from `engine`;
  `tailwindcss-animate` from `ui`; unused `@angular/*` peers from `icons-svg`.
- **Missing added:** `@openfin/workspace` peer on `host-openfin`;
  `ag-grid-enterprise` on `config-browser`; `@vitejs/plugin-react` on `app`;
  `tailwindcss` devDep on `design-system`.
- `sideEffects: ["*.css"]` and a `files` allowlist on all 22 packages, so
  tarballs no longer ship `src/`, tests or tsconfigs.

## 7. `--radius` custom-property cycle (`11793a3f`)

Found while browser-verifying the CSS split: our Button computed
`border-radius: 0px` even though the winning rule was correct.

`starui-tokens.css` defined `--radius: 2px` and `--radius-sm/md/lg/xl:
var(--radius)`, while the compat layer re-aliased `--radius: var(--radius-md)`.
That is a **custom-property cycle**, and CSS makes cyclic properties invalid
at computed-value time — so `--radius`, all four scale steps, and every
`--ds-radius-*` alias resolved to the **empty string**. Every
`rounded-sm/md/lg/xl` utility fell back to the `0px` initial value.
`--radius-full` was never in the cycle, which is why pills and avatars looked
right and nothing else did.

**Pre-existing** — it affected the in-repo demo apps identically.

## 8. Monaco → CodeMirror 6 (`5cbfa0f4`)

Lazy editor chunk in the built star-demo: **4.43 MB → 0.38 MB (91% smaller)**,
no separate vendor chunk. `node_modules` 74 MB → 2.7 MB for the editor.
Feature parity kept and the public props/API unchanged, so no call site moved.

The swap deleted 13 files of Monaco-only workaround, including a fake
web-worker environment, a 97-line key-bridge module (Monaco's hidden-textarea
input path **drops keystrokes** in popped-out windows and transformed
containers), the `editContext:false` time-bomb for that same bug, and a
decoration-based placeholder.

## Verification standard used

In-repo builds hide missing deps via hoisting and source aliases, and a
successful build proves nothing about what renders. So:

1. `npx turbo run typecheck build test` — **64/64 tasks**.
2. `npm run typecheck:apps` clean; star-demo builds.
3. **Two scratch apps built outside the workspace**, installing from packed
   tarballs with no aliases / tsconfig paths / Tailwind config — one
   zero-config, one running its **own** Tailwind. Clean `npm install` (no
   `--force`, no `--legacy-peer-deps`), `tsc --noEmit` 0, `vite build` 0.
4. **Browser verification via Playwright** against the built output —
   computed styles, `document.fonts`, and a request log.

What the browser checks actually established:

- Consumer's own `h1` keeps `margin-top: 17.42px`; `ul` keeps `disc` /
  `40px` — our sheet does not touch their markup.
- Our Button: `Inter`, `border-radius: 2px`, themed background — correct
  **without** `reset.css`.
- Inter + JetBrains Mono report `loaded`; **zero** external requests.
- `vite build` emitted `assets/data-services-worker-<hash>.js`, the page
  fetched it, and the `SharedWorker` constructed — with no config touched.
- Browser-only consumer: `node_modules/@openfin` **absent**.

## Open items

1. **Worker bootstrap payload is never read** — *confirmed bug, not fixed.*
   `writeWorkerBootstrapPayload` persists `appId` / `userId` /
   `configServiceRestUrl` / `seedConfigUrl` to **localStorage**, but
   `defaultEntry.ts` reads it back **inside the SharedWorker**, where neither
   `localStorage` nor `sessionStorage` exists — `readCrossWindowItem` returns
   `null`, so all four are **always `undefined`** and the worker's
   ConfigManager silently runs local/anonymous. Invisible in the demos (local
   Dexie anyway); would silently break any consumer pointing at a REST config
   service.
   **Fix shape:** a `postMessage` handshake on first port connect. There is no
   existing client→worker handshake to extend, so it needs a new protocol
   message plus port-adoption plumbing in `installSharedWorkerHub` (which
   already queues ports in `entry.ts`). Note `defaultEntry` awaits
   `configManager.init()` *before* `installSharedWorkerHub`, so it has the same
   dropped-first-port race the hub's own comment warns about. Wants a runtime
   check against star-demo with a live config service — not verifiable
   headlessly.
2. **Duplicate worker chunk in demo output** — in-repo demos still pass an
   explicit `?url`, so their build emits both that asset and the new fallback
   chunk (~249 KB duplicate). Demo output only, never consumer output. Fix by
   dropping the `?url` import from the demos, but star-demo runs under OpenFin
   so that wants runtime testing.
3. **Test coverage / Sonar LCOV** — deferred by explicit instruction
   ("lets worry about coverage later lets finish with packaging"). None of it
   exists yet: no `sonar-project.properties`, no `run-test-coverage.mjs`, no
   `check-package-coverage.mjs`; 0/15 vitest configs have coverage blocks and
   7 packages lack real test scripts.
4. **ESLint `unicorn/filename-case`** per-bucket enforcement remains a
   follow-up (per `CLAUDE.md`); conventions are review-enforced today.
